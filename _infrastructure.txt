PROJECT SUMMARY
This project is a static website generated by Eleventy (11ty) that acts as a comprehensive digital catalog for a mineral collection. It uses a headless CMS for data entry, a Python script for data conversion, and a custom image optimization pipeline. The site features a dynamic homepage with data visualizations, a highly filterable data table, and individual detail pages for each specimen. The site uses STL 3D models to render interactive crystal habits.

HOSTING AND INFRASTRUCTURE
The codebase is hosted on GitHub. Cloudflare Pages is configured to listen to the main branch of the GitHub repository. When a push is detected, Cloudflare triggers a build command which runs the image optimization script and the Eleventy build process. The outputted static files are deployed to Cloudflare's edge network. The src/_headers file instructs Cloudflare and the user's browser to cache images, 3D models, and assets for extended periods.

DATA ARCHITECTURE
The site is driven by several data files located in the src/_data directory. The data flows from the master CSV/Excel file, through the Python script, and into two main JSON files. The YAML files act as independent reference databases that are looked up during the Eleventy build process.

SPECIMENS.CSV AND SPECIMENS.XLSX
These are the master data files maintained by the user. The CSV is the raw export from the Excel spreadsheet. It contains rows representing individual specimens and columns for all metadata fields (shelf, box, number, color, shiny, type, display_name, main, habit, matrix, from_who, from_where, country, date_acquired, weight_g, quantity, price, tier, description, wip).

CSV_TO_JSON.PY
This Python script parses the specimens.csv file and generates specimens.json and modelgallery.json. It cleans the data, parses the color integer IDs into HEX codes using a predefined palette, combines location and country fields into a single origin string, generates a unique slug for each specimen based on its box and number, and resolves the appropriate 3D model file names based on whether a specific or generic STL file exists.

SPECIMENS.JSON
This is the primary data source for the entire site. It is a large array of objects. Each object represents a single specimen and contains the following keys:
- slug (String): The unique identifier used in the URL (e.g., "3-3").
- shelf, box, number (Integers): Physical location data.
- colors (Array of Strings): A list of up to three HEX color codes representing the dominant colors.
- shiny (Boolean): Indicates if the specimen has a shiny finish.
- type (String): The categorization (Crystal, Gem, Rock, Mineral, Geode, Fossil).
- name (String): The display name.
- main (String): The primary mineral or material composition.
- habit (String): The crystal habit or shape.
- matrix (String): The host rock or matrix information.
- from_who (String): The source or person who provided it.
- from_where (String): The geographic origin.
- date_acquired (Integer): The year of acquisition.
- weight_g (Float): Weight in grams.
- quantity (Integer): Number of pieces.
- price (Float): Acquisition cost.
- tier (Integer): A ranking from 1 to 5.
- description (String): Textual notes.
- wip (Boolean): Work in progress flag.
- has_specific (Boolean): Indicates if a specific 3D model exists for this exact mineral and habit combination.
- models (Array of Objects): Contains metadata linking to the specific 3D model files, including the file name.

MODELGALLERY.JSON
This file is generated by the Python script. It contains a unique list of 3D model shapes. If multiple specimens share the exact same STL file (determined by an MD5 hash), they are grouped together here. This file drives the "3D Models" view on the collection page. It includes the habit name, the file name, an array of species that use this model, the total specimen count, and a display label.

MINERALI.YML
This is a comprehensive reference database for minerals. It is formatted as a YAML dictionary. The keys are mineral names (e.g., Pirite, Quarzo). Each key contains an object with detailed scientific data, including:
- formula (String): The chemical formula.
- sistema (String): The crystal system.
- classe (String): The crystal class.
- categoria (String): The mineral category.
- famiglia (String): The mineral family.
- nota (String): General notes.
- composizione (String): Chemical composition details.
- abiti (Object): A nested dictionary of crystal habits specific to this mineral. Each habit key contains the Italian name of the habit, a descriptive note, and reference to the 3D model.
This data is used on the specimen detail page to display chemical information and to resolve the correct 3D model to load based on the specimen's "main" and "habit" properties.

MATERIALI.YAML
This file functions identically to minerali.yml but is used for non-mineral specimens, such as rocks, organic materials, or synthetics.

PAGE GENERATION AND TEMPLATING
The site uses Liquid templating to parse the data files and generate HTML.

BASE.LIQUID
This is the global layout file. It contains the HTML shell, loads the global CSS variables and base styles, implements the global loader animation, and dynamically loads page-specific CSS and JavaScript based on the current URL. It also defines the import map for Three.js.

INDEX.LIQUID (HOMEPAGE)
This page performs heavy data aggregation using Liquid filters. It calculates the total number of specimens, unique species (by parsing the main field), total pieces, total weight, total invested capital, and counts for shiny and WIP items. It builds a custom JSON string to feed a world map visualization by searching the from_where field against a hardcoded list of regions. It also constructs a JSON object representing the "Explore" feature, which groups data by shelf and box.

COLLECTION.LIQUID (CATALOG)
This page iterates over specimens.json to build a data table and a gallery view. It formats the colors field into CSS gradients for row backgrounds. It includes a robust client-side filtering and sorting engine written in vanilla JavaScript, capable of filtering by type, tier, colors, flags, and text search. It also uses modelgallery.json to render the 3D Models view.

SPECIMEN.LIQUID (DETAIL PAGE)
This file uses Eleventy's pagination feature to generate a unique page for every item in specimens.json. It calculates the previous and next items in the collection array. It extracts the region ID from the from_where field to highlight the correct country on an SVG world map. It also matches the main and habit fields against minerali.yml or materiali.yaml to pull in chemical formulas and link the correct 3D model for rendering.

ASSET MANAGEMENT AND BUILD PROCESS

IMAGES
Raw images in the originals folder are processed by scripts/optimize-images.js. This script uses the Sharp library to generate four web-optimized versions of every image: display (1800px width), large (2800px width), card (1000px width), and thumb (480px width). These are saved into subdirectories within src/images/the_collection.

3D MODELS
The src/habits folder contains STL files representing crystal shapes. The site uses Three.js (hosted locally in src/assets/js) along with STLLoader.js to render these models. The collection page and specimen detail pages contain separate JavaScript modules (collection-3d.js and specimen-3d.js) that handle the rendering logic, including a fallback system to load a generic habit model if a species-specific model is unavailable.

JAVASCRIPT AND CSS
All CSS and JavaScript are extracted from the Liquid files and stored in the src/assets directory. The base layout dynamically links the correct stylesheets and scripts based on the page being viewed. Three.js and its dependencies are hosted locally to ensure fast loading and caching.

SECURITY AND CONTENT MANAGEMENT
The site includes Sveltia CMS, accessed via the /admin route. This provides a graphical interface to edit the specimens.json file. Authentication is handled via GitHub OAuth, meaning only users with write access to the GitHub repository can log in and make changes. When changes are saved, the CMS commits the updated JSON file directly to the repository, triggering a new build and deployment on Cloudflare.
