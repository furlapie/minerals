PROJECT SUMMARY
This project is a static website generated by Eleventy (11ty) that acts as a comprehensive digital catalog for a mineral collection. It uses a headless CMS for data entry, Python scripts for data derivation, and a custom image optimization pipeline. The site features a dynamic homepage with data visualizations, a highly filterable data table, and individual detail pages for each specimen, using STL 3D models to render interactive crystal habits.

HOSTING AND INFRASTRUCTURE
The codebase is split into two distinct GitHub repositories, both deployed on Cloudflare. The primary repository, "minerals", is hosted on Cloudflare Pages and listens to the main branch. When a push is detected (either manually or via the CMS), Cloudflare triggers the build command which runs the Python derivation script, the image optimization script, and the Eleventy build process. The outputted static files are deployed to Cloudflare's edge network. The src/_headers file instructs Cloudflare and the user's browser to cache images, 3D models, and assets for extended periods. The second repository, "mineral-cms-auth", is deployed as a Cloudflare Worker and serves as the dedicated OAuth backend required by Sveltia CMS to securely authenticate users against GitHub.

DATA ARCHITECTURE
The site is driven by several data files located in the src/_data directory. While the data originally flows from the master CSV/Excel file through a Python script into JSON, day-to-day updates are now handled directly by editing specimens.json via the Sveltia CMS. The YAML files act as independent reference databases that are looked up during the Eleventy build process.

SPECIMENS.CSV AND SPECIMENS.XLSX
These are the master backup files maintained by the user. The CSV is the raw export from the Excel spreadsheet. It contains rows representing individual specimens and columns for all metadata fields.

CSV_TO_JSON.PY
This Python script parses the specimens.csv file and generates the initial specimens.json and modelgallery.json. It cleans the data, parses the color integer IDs into HEX codes using a predefined palette, combines location and country fields into a single origin string, generates a unique slug for each specimen based on its box and number, and resolves the appropriate 3D model file names based on whether a specific or generic STL file exists.

DERIVE.PY
This is the critical build script that runs immediately before Eleventy. It reads the current specimens.json (which may have been edited by the CMS) and recomputes all derived data. It calculates the models array and has_specific boolean for every specimen by checking the habits directory. It hashes the STL files to group identical 3D shapes into modelgallery.json. Crucially, it captures the cms_index (the array position) for every item before sorting the JSON by shelf, box, and number, ensuring that the CMS edit links on the frontend remain accurate. It also acts as the bridge for CMS image uploads: when a user drops a photo into the CMS, Sveltia saves it under its original filename, but derive.py copies and renames it to the strict box.number.ext format inside the originals folder so the optimization script can find it.

SPECIMENS.JSON
This is the primary data source for the entire site. It is a large array of objects. Each object represents a single specimen and contains keys for slug, physical location (shelf, box, number), colors, shiny, type, name, main, habit, matrix, origin details, date_acquired, weight_g, quantity, price, tier, description, wip, and the new photo field for CMS uploads. It also contains derived keys injected by derive.py: has_specific, models, and cms_index (used for routing to the correct CMS edit URL).

MODELGALLERY.JSON
This file is generated by the Python script. It contains a unique list of 3D model shapes. If multiple specimens share the exact same STL file (determined by an MD5 hash), they are grouped together here. This file drives the "3D Models" view on the collection page. It includes the habit name, the file name, an array of species that use this model, the total specimen count, and a display label.

MINERALI.YML AND MATERIALI.YAML
These are comprehensive reference databases for minerals and non-minerals respectively. Formatted as YAML dictionaries, the keys are mineral names (e.g., Pirite, Quarzo). Each key contains an object with detailed scientific data including formula, sistema, classe, categoria, famiglia, nota, composizione, and a nested abiti dictionary of crystal habits specific to that mineral. This data is used on the specimen detail page to display chemical information and to resolve the correct 3D model to load based on the specimen's main and habit properties.

PAGE GENERATION AND TEMPLATING
The site uses Liquid templating to parse the data files and generate HTML.

BASE.LIQUID
This is the global layout file. It contains the HTML shell, loads the global CSS variables and base styles, implements the global loader animation, and dynamically loads page-specific CSS and JavaScript based on the current URL. It also defines the import map for Three.js.

INDEX.LIQUID (HOMEPAGE)
This page performs heavy data aggregation using Liquid filters. It calculates the total number of specimens, unique species (by parsing the main field), total pieces, total weight, total invested capital, and counts for shiny and WIP items. It builds a custom JSON string to feed a world map visualization by searching the from_where field against a hardcoded list of regions. It also constructs a JSON object representing the "Explore" feature, which groups data by shelf and box.

COLLECTION.LIQUID (CATALOG)
This page iterates over specimens.json to build a data table and a gallery view. It formats the colors field into CSS gradients for row backgrounds. It includes a robust client-side filtering and sorting engine written in vanilla JavaScript, capable of filtering by type, tier, colors, flags, and text search. It also uses modelgallery.json to render the 3D Models view.

SPECIMEN.LIQUID (DETAIL PAGE)
This file uses Eleventy's pagination feature to generate a unique page for every item in specimens.json. It calculates the previous and next items in the collection array. It extracts the region ID from the from_where field to highlight the correct country on an SVG world map. It also matches the main and habit fields against minerali.yml or materiali.yaml to pull in chemical formulas and link the correct 3D model for rendering. It uses the injected cms_index to build the direct edit link pointing to the exact Sveltia CMS entry URL.

ASSET MANAGEMENT AND BUILD PROCESS

IMAGES
Raw images are uploaded via the Sveltia CMS image widget directly into the originals folder. Because CMS uploads retain their original filenames, derive.py steps in during the build to copy and rename them to the expected box.number.ext format. Once the files in originals are standardized, scripts/optimize-images.js uses the Sharp library to generate four web-optimized versions of every image: display (1800px width), large (2800px width), card (1000px width), and thumb (480px width). These are saved into subdirectories within src/images/the_collection.

3D MODELS
The src/habits folder contains STL files representing crystal shapes. The site uses Three.js (hosted locally in src/assets/js) along with STLLoader.js to render these models. The collection page and specimen detail pages contain separate JavaScript modules (collection-3d.js and specimen-3d.js) that handle the rendering logic, including a fallback system to load a generic habit model if a species-specific model is unavailable.

JAVASCRIPT AND CSS
All CSS and JavaScript are extracted from the Liquid files and stored in the src/assets directory. The base layout dynamically links the correct stylesheets and scripts based on the page being viewed. Three.js and its dependencies are hosted locally to ensure fast loading and caching.

SECURITY AND CONTENT MANAGEMENT
The site includes Sveltia CMS, accessed via the /admin route. Authentication is handled via the separate mineral-cms-auth Cloudflare Worker, which manages GitHub OAuth so only users with write access to the repository can log in. When changes are saved, the CMS commits the updated JSON and image files directly to the repository, triggering a new build. The CMS configuration makes extensive use of required: false to keep optional fields clean, disables the intrusive preview pane in favor of a full-width editor, and includes a custom CSS block in the admin index.html to style the interface with the site's dark/gold theme. Because Sveltia identifies entries by their array position rather than their slug, the derive.py script must record the position before any sorting occurs, ensuring the frontend edit links route correctly to /admin/#/collections/specimens/entries/{cms_index}.
